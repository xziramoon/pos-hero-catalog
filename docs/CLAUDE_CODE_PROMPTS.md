# คำสั่งสำหรับ Claude Code — ทีละเฟส

วิธีใช้: เปิด Claude Code ในโฟลเดอร์ **pos-lan** แล้วคัดลอกกล่องของเฟสที่จะทำไปวาง ทำเสร็จหนึ่งเฟส ให้ Boss ทดสอบและรวม PR ก่อน แล้วค่อยเริ่มเฟสถัดไป

ทุกเฟสมีกติกาเดียวกันนี้ (ใส่ไว้ในกล่องคำสั่งให้แล้ว):
- อ่าน `docs/CATALOG_HERO_SPEC.md` ทั้งไฟล์ก่อนเริ่ม
- สร้าง branch ตามที่กำหนด แล้วเปิด PR **ห้าม push ลง main**
- ห้ามแตะโค้ดส่วนรับเงิน และ `npm test` เดิมต้องผ่าน
- ห้ามใส่ URL ลับ, key หรือ token ลงในโค้ด
- จบงานแล้วสรุปเป็นภาษาไทย แล้วหยุดรอ Boss ทดสอบ

---

## เฟส 1 — Cloudflare Worker

```
อ่าน docs/CATALOG_HERO_SPEC.md ให้ครบทั้งไฟล์ก่อนเริ่ม แล้วทำ "เฟส 1: Worker" ตามหัวข้อ 4, 5 และ 10

กติกา:
- สร้าง branch feat/catalog-worker แล้วเปิด PR ห้าม push ลง main
- ห้ามแตะโค้ดส่วนรับเงิน (inbox, LAN relay, UDP, พิมพ์) และ test/smoke.js เดิมต้องผ่านเหมือนเดิม
- เขียน catalog/shared/merge.js พร้อม unit test แล้วใช้ไฟล์เดียวกันทั้งใน Worker และในแอป
- เพิ่ม DO Catalog (SQLite) + R2 binding CATALOG_IMAGES ใน wrangler.toml โดยใช้ migration tag v2
- เพิ่ม test/catalog-smoke.js ให้ npm test รันทั้งชุดเดิมและชุดใหม่
- อัปเดต docs/cloudflare-setup.md เป็นภาษาไทย ให้มีขั้นเปิด R2, สร้าง bucket pos-hero-catalog และตั้ง Catalog Key / write token
- ห้ามใส่ URL ของ Google Sheet, ImgBB key หรือ token ใดๆ ลงในโค้ด

พอทำเสร็จ สรุปให้ผมเป็นภาษาไทยว่า:
1. แก้ไฟล์อะไรบ้าง
2. คำสั่งที่ผมต้องรันเองบนเครื่อง
3. อะไรที่ยังไม่ได้ทำ หรือมีจุดไหนในสเปกที่ต้องให้ผมตัดสินใจ
แล้วหยุดรอผมทดสอบก่อนไปเฟส 2
```

## เฟส 2 — หน้าต่างกระเป๋าสินค้า (ข้อมูลในเครื่อง ยังไม่ซิงก์)

```
อ่าน docs/CATALOG_HERO_SPEC.md ให้ครบทั้งไฟล์ก่อนเริ่ม แล้วทำ "เฟส 2: หน้าต่างกระเป๋า" ตามหัวข้อ 3, 6.1 และ 7
ดูดีไซน์อ้างอิงที่ docs/catalog-design/canvas/Main.dc.html (เป็นไฟล์ดีไซน์ ไม่ต้องเอาไปรันตรงๆ ให้ดูโครงหน้า สี ขนาด และพฤติกรรมตอนคลิก)

กติกา:
- สร้าง branch feat/catalog-window แล้วเปิด PR ห้าม push ลง main
- โค้ดใหม่อยู่ใน catalog/ และ renderer/catalog/ และใช้ preload แยก (window.catalogAPI) ส่วน main.js แก้แค่จุดเชื่อม
- ใช้ตัวแปร --hero-* จาก theme-hero.css ห้าม hardcode สี และต้องเปลี่ยนธีมตามหน้าต่างหลัก
- คลิกช่อง = คัดลอกรหัส + แอนิเมชัน COPIED / คลิกขวา = แก้ไข / F2 = เปิด-ปิด / Enter = คัดลอกเมื่อเหลือผลเดียว
- ตาราง slot ต้อง virtualize ทดสอบด้วยข้อมูลปลอม 10,000 ชิ้นแล้วต้องยังเลื่อนลื่น
- ปุ่มบน mini widget: ประเมินผลกระทบกับ MINI_WIDTH และแอนิเมชันย่อ/ขยายก่อน (สเปกหัวข้อ 7.1) ถ้าเสี่ยง ให้ทำแค่ปุ่มในแถบหัวไปก่อน แล้วบอกผม
- ห้ามแตะโค้ดส่วนรับเงิน และ npm test เดิมต้องผ่าน

พอทำเสร็จ สรุปเป็นภาษาไทย: แก้ไฟล์อะไรบ้าง, วิธีลองใช้, ภาพหน้าจอ (ถ้าทำได้), และเรื่องที่ต้องให้ผมตัดสินใจ แล้วหยุดรอผมทดสอบ
```

## เฟส 3 — ระบบตัดแต่งรูป + หน้าปรับรูป

```
อ่าน docs/CATALOG_HERO_SPEC.md ให้ครบทั้งไฟล์ก่อนเริ่ม แล้วทำ "เฟส 3: ระบบรูป" ตามหัวข้อ 8, 11, 12.1 และภาคผนวก A
ต้นแบบ Python อยู่ที่ docs/catalog-prototype/clean_pipeline.py ให้แปลงเป็น OpenCV.js ที่รันใน Web Worker โดยใช้ค่าตัวเลขเดิมทุกตัว
ดีไซน์หน้าปรับรูป: docs/catalog-design/canvas/Crop.dc.html / รูปทดสอบ: test/fixtures/photos/ / ผลจากต้นแบบไว้เทียบ: test/fixtures/expected-prototype/

กติกา:
- สร้าง branch feat/catalog-images แล้วเปิด PR ห้าม push ลง main
- เขียน pipeline เป็นอาร์เรย์ของขั้นตอน เปิด/ปิดและตั้งค่าได้จาก config (หัวข้อ 12.1)
- เก็บรูปต้นฉบับไว้เสมอ และทุกค่าการตัดแต่งต้องใช้กับต้นฉบับแล้วได้ผลเหมือนเดิมทุกครั้ง
- ทำระบบให้คะแนน ok/check/retake และถอยไปใช้แบบไม่ลบพื้นหลังเมื่อ mask แหว่ง (หัวข้อ 8.3)
- ห้ามปรับสีแรงกว่าที่สเปกกำหนด (ห้ามใช้ CLAHE)
- หน้าปรับรูปต้องมี: 2 กรอบ (ช่องตาราง/การ์ด), ซูม, หมุน, แปรงแก้ขอบ, สวิตช์ลบพื้นหลัง/ตั้งตรง, ความสว่าง, ความคม, กดค้างดูรูปก่อนแก้
- เขียน test แบบ snapshot ด้วยรูป 8 เคส ผลที่คาดหวังอยู่ในตารางหัวข้อ 13

พอทำเสร็จ สรุปเป็นภาษาไทย: ผลของรูปแต่ละเคส (ok/check/retake), ภาพเทียบก่อน/หลัง และเรื่องที่ต้องให้ผมตัดสินใจ แล้วหยุดรอผมทดสอบ
```

## เฟส 4 — ซิงก์ระหว่างเครื่อง

```
อ่าน docs/CATALOG_HERO_SPEC.md ให้ครบทั้งไฟล์ก่อนเริ่ม แล้วทำ "เฟส 4: ซิงก์" ตามหัวข้อ 4.3, 5 และ 6

กติกา:
- สร้าง branch feat/catalog-sync แล้วเปิด PR ห้าม push ลง main
- ใช้ outbox + backoff, ส่งรูปขึ้นก่อน item ที่อ้างถึงรูปนั้น, ดึงด้วย changes?since= เท่านั้น
- รวมข้อมูลด้วย catalog/shared/merge.js ตัวเดียวกับ Worker
- writeToken เก็บไว้ที่ main process เท่านั้น ห้ามอยู่ใน renderer หรือ localStorage
- ไฟสถานะ เขียว/เหลือง/แดง + แถบเตือนเมื่อซิงก์ไม่ได้นาน + สั่ง pull ใหม่เมื่อ network-changed
- สำรอง db.json วันละครั้ง เก็บ 14 ไฟล์
- เขียน test สำหรับ outbox และ merge ตามหัวข้อ 13

พอทำเสร็จ สรุปเป็นภาษาไทย: วิธีทดสอบด้วยสองเครื่อง (รวมกรณีถอดเน็ตแล้วเสียบกลับ) และเรื่องที่ต้องให้ผมตัดสินใจ แล้วหยุดรอผมทดสอบ
```

## เฟส 5 — ย้ายข้อมูลเดิม

```
อ่าน docs/CATALOG_HERO_SPEC.md ให้ครบทั้งไฟล์ก่อนเริ่ม แล้วทำ "เฟส 5: ย้ายข้อมูล" ตามหัวข้อ 9.2 (Google Sheet) ก่อน แล้วค่อย 9.1 (catalog-data.json) พร้อมปุ่มจัดรูปทั้งหมด (8.6)

กติกา:
- สร้าง branch feat/catalog-import แล้วเปิด PR ห้าม push ลง main
- URL ของชีตให้ผู้ใช้วางเองในหน้านำเข้าแล้วเก็บไว้ใน config ห้าม hardcode หรือ commit ไว้ในโค้ด
- แกะข้อมูลที่เป็น JSON ในเซลล์เดียวของ CSV ตามวิธีในสเปก รหัสสินค้าต้องเป็น string เสมอ
- นำเข้าซ้ำแล้วต้องไม่ซ้ำ (จับคู่ด้วย legacyId แล้วค่อย code) และไม่ทับของที่แก้ไว้ในระบบใหม่
- ดาวน์โหลดรูปพร้อมกันไม่เกิน 4 รูป, ดาวน์โหลดไม่ได้ให้ข้ามไปและเก็บลิงก์เดิมไว้, กดหยุดแล้วทำต่อจากจุดเดิมได้
- ห้ามเขียนอะไรกลับไปที่ Google Sheet และห้ามใช้ ImgBB key
- เขียน test/migrate-sheet.test.js ด้วย fixture ที่สร้างเอง

พอทำเสร็จ สรุปเป็นภาษาไทยว่าต้องกดตรงไหน และผลที่ควรได้ (227 สินค้า) แล้วหยุดรอผมทดสอบกับข้อมูลจริง
```
