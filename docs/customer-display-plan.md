# แผนโปรแกรม "จอลูกค้า" (Customer Display) สำหรับ Sea & Hill POS

ร้านอึ้งลักเส็ง · เขียนเพื่อส่งต่อให้ Claude Code ทำ · 22/11/2569

## 1. เป้าหมาย

ทำจอแยกหันหาลูกค้า แสดง **สินค้าที่ยิง, ราคา, ยอดรวม** และตอนจ่ายเงินแสดง **รับเงิน / เงินทอน**
ใช้แท็บเล็ตหรือมือถือเปิด Chrome ผ่าน WiFi ในร้าน (หรือจะใช้จอที่สองของคอมก็ได้)

## 2. ทำไมใช้วิธีนี้ (สิ่งที่ทดสอบแล้ว)

- Sea & Hill POS v1.1.17.27268 (build 2021-01-20, .NET WinForms) มีแท็บ Customer Display แต่ **ใช้ไม่ได้**
  - แบบ Serial: ช่อง Data Bits ใส่ตัวเลือกของ StopBits (None/One/Two/OnePointFive) ทำให้เปิดพอร์ตไม่ได้ → `ArgumentOutOfRangeException: DataBits must be between 5 and 8` ค่าเก็บบน cloud แก้เองไม่ได้
  - แบบ Android: ไม่มีพอร์ตเปิดรอ ไม่มีแอปให้ใช้
- **ทางที่ใช้ได้: UI Automation (อ่านข้อความจากหน้าต่าง POS)** ทดสอบด้วย PowerShell แล้วอ่านได้จริง
- **ห้ามแตะ POS:** โปรแกรมนี้ทำงานแบบอ่านอย่างเดียว ห้ามส่งคีย์บอร์ด ห้ามคลิก ห้ามแก้ไฟล์หรือ registry ของ Sea & Hill

## 3. ข้อมูลที่อ่านได้ (ยืนยันแล้ว)

หน้าต่างหลัก: top-level window ที่ `Name` มีคำว่า `Sea And Hill POS`
ทุกช่องที่ต้องใช้เป็น `ClassName` ที่ขึ้นต้นด้วย `WindowsForms10.STATIC` ค่าอยู่ใน `Current.Name`

> **ห้ามใช้ AutomationId** เพราะเป็นเลข HWND ที่เปลี่ยนทุกครั้งที่เปิด POS ให้หาช่องจาก **รูปแบบข้อความ** แทน

| ข้อมูล | วิธีหา | ตัวอย่าง |
|---|---|---|
| ยอดรวม (Total) | STATIC ที่ข้อความเป็นตัวเลขล้วน `^-?[\d,]+\.\d{2}$` (มีช่องเดียวในหน้าหลัก) | `265.00` |
| รายการล่าสุด (แถบเหลือง) | STATIC ที่ตรงกับรูปแบบในข้อ 4 | `8850822011676/เค.เอ. ไฮยาอินเทนส์เซรั่ม 7กรัม/แพ็ค/@ 1.00 x 225.00 = 225.00` |
| เลขที่ใบเสร็จ | STATIC ที่ตรงกับ `^POS\d+-\d+$` | `POS02261122-00065` |
| รหัสเครื่อง | STATIC `^POS\d+$` | `POS02` |

ตารางรายการ (Line 1–8) **อ่านไม่ได้** เพราะเป็น custom grid เลยต้องสร้างรายการเองจากแถบเหลือง

## 4. รูปแบบแถบเหลือง (ทดสอบแล้วทุกเคส)

```
[prefix : ]<barcode>/<ชื่อสินค้า>/<หน่วย>/@ <จำนวน> x <ราคา> = <ยอด>
```

| prefix | เกิดเมื่อ | ความหมายของจำนวน | การกระทำ |
|---|---|---|---|
| (ไม่มี) | ยิงสินค้าใหม่ หรือกด +1 / -1 | **จำนวนรวมของบรรทัดนั้น** | upsert ตาม barcode |
| `เพิ่ม : ` | ยิงสินค้าตัวเดิมซ้ำ | จำนวนรวม (เช่น `@ 2.00 x 225.00 = 450.00`) | upsert ตาม barcode |
| `ลบ : ` | ลบรายการ (ปุ่ม Del หรือ `***<line>`) | – | ลบ barcode นั้นออก |

การ parse: ชื่อสินค้าอาจมีเครื่องหมาย `/` อยู่ข้างใน ให้ตัดจาก**ขวาไปซ้าย**
1. ตัด prefix `เพิ่ม :` หรือ `ลบ :` ออก (ยอมให้มีช่องว่างรอบ `:`)
2. barcode = ข้อความก่อน `/` ตัวแรก
3. แยกส่วนท้ายด้วย `/@ ` ตัวสุดท้าย → `จำนวน x ราคา = ยอด` (ตัด comma ออกก่อนแปลงเป็นตัวเลข)
4. หน่วย = ส่วนหลัง `/` ตัวสุดท้ายก่อน `/@`, ชื่อ = ส่วนที่เหลือตรงกลาง

## 5. การทำงานของหน้าหลัก (state machine)

อ่านค่าทุก **300 ms** แล้วเทียบกับค่าครั้งก่อน

- **เลขที่ใบเสร็จเปลี่ยน** → บิลใหม่: ล้างรายการ แล้วจำข้อความแถบเหลืองตอนนั้นไว้เป็น **baseline**
  (แถบเหลืองยังค้างรายการจากบิลก่อน **ห้ามนับ** จนกว่าข้อความจะเปลี่ยนไปจาก baseline)
- **ข้อความแถบเหลืองเปลี่ยน** → parse แล้ว upsert หรือลบตาม prefix และไฮไลต์รายการล่าสุด
- **Total ใช้ค่าจาก POS เสมอ** ห้ามคำนวณเอง
- **ตรวจความตรงกัน:** ถ้า `sum(ยอดแต่ละรายการ)` ≠ Total (ต่างเกิน 0.01) เช่น หลัง Recall Bill, ส่วนลด, แก้ราคา
  → ซ่อนรายการ แสดงแค่ **รายการล่าสุด + Total** (fallback) และเขียน log ไว้ดีบัก
- Total = 0 และไม่มีรายการ → หน้าต้อนรับ (โลโก้อึ้งลักเส็ง / ริสุซัง / โปรโมชั่น)

## 6. หน้าจ่ายเงิน (หน้าต่าง Pay)

- เป็น top-level window แยก `Name = "Pay"` อยู่ใน **process เดียวกับ POS** ให้เช็กทุกรอบด้วย ProcessId
- ช่องตัวเลขเป็น `WindowsForms10.EDIT` ค่าอยู่ใน `Current.Name`
- **ลำดับใน tree ไม่ตรงกับป้ายชื่อ** ต้องจับคู่ด้วย `BoundingRectangle`:
  สำหรับป้าย (STATIC) แต่ละตัว ให้หา EDIT ที่ศูนย์กลางแนวตั้งอยู่ในช่วงความสูงของป้าย, `EDIT.Left >= ป้าย.Right` แล้วเลือกตัวที่ใกล้ที่สุด

| ป้าย | ใช้แสดง | ตัวอย่างค่า |
|---|---|---|
| `รวมทั้งสิ้น :` | ยอดที่ต้องจ่าย | `225.00` |
| `คงเหลือทั้งสิ้น :` | ยอดหลังปัดเศษหรือส่วนลด (ถ้ามี ให้ใช้ค่านี้) | `225.00` |
| `ชำระเงินสด :` | รับเงิน | `500` (อาจไม่มีทศนิยม) |
| `เงินทอน :` | เงินทอน | `275.00` |
| `เงินโอน :` | (เฟส 2) ยอดโอน | – |

- Pay เปิดอยู่ → จอลูกค้าขึ้น "ยอดชำระ / รับเงิน / เงินทอน" ตัวใหญ่
- Pay ปิด และเลขที่ใบเสร็จเปลี่ยน → บันทึกบิลแล้ว: ขึ้น "ขอบคุณครับ" + เงินทอนล่าสุดค้างไว้ ~8 วินาที แล้วกลับหน้าต้อนรับ
- Pay ปิด แต่เลขที่ใบเสร็จเดิม → กด Cancel: กลับไปหน้ารายการ

## 7. สถาปัตยกรรม (ต่อยอดจอลูกค้าของ QR ล็อกยอดใน repo นี้)

repo นี้ **มีจอลูกค้าอยู่แล้ว** ใน `qrlock/` ห้ามสร้างเซิร์ฟเวอร์หรือพอร์ตใหม่ ให้ใช้ของเดิม:
- `qrlock/display-server.js`: HTTP + WebSocket (เขียนเอง ไม่มี library) เสิร์ฟ `/display` และ `/ws` พอร์ต `cfg.displayPort` (ค่าเริ่ม 8080, มี firewall rule ให้แล้ว)
- `qrlock/display.html`: render ตาม `m.type` (`idle` / `show_qr` / `paid` / `expired` / `cancelled`) มีริสุซัง, กันจอดับ, ต่อใหม่อัตโนมัติ
- `qrlock/qrlock-main.js`: `send(msg)` broadcast และจำ `lastMsg` ไว้ให้จอที่เพิ่งต่อเข้ามา
- (ที่ POS02 พอร์ต 8080 และ 8788 ถูกใช้โดย POS Hero เอง: จอลูกค้า qrlock + LAN relay)

```
[Sea & Hill POS] --UI Automation (อ่านอย่างเดียว)--> [custdisplay/pos-reader.ps1] --JSON lines--> [custdisplay/index.js]
                                                         state machine ข้อ 5–6 --> qrlock send() --> display-server (/ws) --> display.html บนแท็บเล็ต
```

1. **โมดูลใหม่ `custdisplay/`** (แยกเหมือน qrlock: โหลดใน main.js ด้วย try/catch, พังแล้วต้องไม่กระทบ POS Hero / รับเงิน / qrlock)
   - `custdisplay/pos-reader.ps1`: PowerShell ทำงานยาว
     - `Add-Type -AssemblyName UIAutomationClient,UIAutomationTypes`
     - **cache element** ของ 3 ช่องหลัก ถ้าเจอ `ElementNotAvailableException` หรือ POS ปิดเปิดใหม่ค่อยค้นใหม่ (ห้าม FindAll ทั้งหน้าต่างทุก 300 ms)
     - ลูปทุก 300 ms ส่ง JSON 1 บรรทัดออก stdout เฉพาะตอนค่าเปลี่ยน (UTF-8, flush ทุกครั้ง) เช่น
       `{"t":"main","receipt":"POS02261122-00070","total":225.00,"line":"..."}` / `{"t":"pay","due":225.00,"cash":500,"change":275.00,"transfer":null}` / `{"t":"pay_closed"}` / `{"t":"pos_missing"}`
     - POS ยังไม่เปิด → ลองใหม่ทุก 2 วินาที ห้าม crash
     - เพิ่มลง `build.files` และ `asarUnpack` แล้วหา path แบบเดียวกับ `build/raw-print.ps1`
   - `custdisplay/logic.js`: parse แถบเหลือง + state machine (pure function ไม่พึ่ง Electron จะได้เขียน unit test ใน `test/` ได้)
   - `custdisplay/index.js`: `spawn('powershell.exe', ['-NoProfile','-ExecutionPolicy','Bypass','-File', readerPath])` อ่าน stdout ทีละบรรทัด, ถ้า process ตายให้ spawn ใหม่ (backoff), kill ตอนแอปปิด, config `custdisplay-config.json` ใน userData (`enabled` ค่าเริ่ม false) + เมนู tray "จอลูกค้า: แสดงรายการสินค้า (เปิด/ปิด)"
2. **แก้ qrlock ให้น้อยที่สุด**
   - export ฟังก์ชันใหม่ เช่น `qrlock.showCart(msg)` ให้ custdisplay ส่งข้อความผ่าน `send()` เดิม
   - **QR มีสิทธิ์ก่อนเสมอ:** ถ้า `sessions.waiting()` อยู่ (กำลังโชว์ QR) หรือเพิ่งโชว์ `paid`/`expired`/`cancelled` ภายใน 5 วินาที ให้**ไม่ส่ง** cart ทับ (จำ state ล่าสุดไว้ แล้วส่งตอนจบ)
   - ตอนนี้ display server เปิดเฉพาะตอน "QR ล็อกยอด" เปิดอยู่ (`start()`) ให้แยกการเปิดเซิร์ฟเวอร์ออกมา เปิดเมื่อ**อย่างใดอย่างหนึ่ง**เปิดอยู่ (qrlock หรือ custdisplay) โดยไม่เปลี่ยนพฤติกรรมเดิมของ qrlock
3. **`qrlock/display.html`: เพิ่ม type ใหม่** (ไม่แก้หน้าเดิม)
   - `cart` `{items:[{name,unit,qty,price,amount}], last:barcode, total, fallback:bool}`: รายการทางซ้าย รายการล่าสุดไฮไลต์และเลื่อนลงอัตโนมัติ ยอดรวมตัวใหญ่ขวาล่าง ถ้า `fallback` แสดงแค่รายการล่าสุด + ยอดรวม
   - `pay` `{due, cash, change}`: ยอดชำระ / รับเงิน / เงินทอน ตัวใหญ่
   - `thanks` `{change}`: ขอบคุณ + เงินทอน แล้วกลับ `idle` ใน ~8 วินาที ใช้ mascot `m-thanks` เดิม
   - ตัวหนังสือไทยใหญ่อ่านจากระยะ 1–1.5 เมตร ใช้สไตล์เดียวกับหน้าที่มีอยู่
4. **ข้อห้ามจาก CLAUDE.md:** ห้ามแตะ logic รับเงิน (inbox, LAN relay, UDP, Pushbullet fallback, พิมพ์สลิป), `test/smoke.js` ต้องผ่าน, ห้ามเปลี่ยน `MINI_WIDTH`/`MINI_HEIGHT`, UI เป็นภาษาไทย, ทำบน branch แยกแล้วเปิด PR ห้าม push ลง main

## 9. ขั้นการพัฒนาและทดสอบ

1. **pos-reader.ps1 อย่างเดียว:** รันใน PowerShell แล้วดู JSON ที่พิมพ์ออกมา แล้วทดสอบกับ POS จริงทุกเคส: ยิงใหม่, ยิงซ้ำ, +1/-1, ลบ, เปิด Pay, Cancel, Save, บิลถัดไป
2. **โหมดบันทึกและเล่นซ้ำ:** บันทึก output ของ pos-reader เป็น `log.jsonl` แล้วให้โมดูลจอลูกค้ามีโหมด replay จากไฟล์ จะได้พัฒนาหน้าเว็บได้โดยไม่ต้องยืนยิงสินค้าจริง
3. หน้าเว็บ + WebSocket ลองบนแท็บเล็ตผ่าน WiFi ร้าน
4. ทดสอบเคสพิเศษ: Hold Bill / Recall Bill, คูณจำนวน (`5*barcode`), ส่วนลด, สมาชิก, ปิดเปิด POS ระหว่างโปรแกรมรันอยู่, POS ค้าง
5. วัด CPU ของ pos-reader (ต้องไม่เกิน ~1–2%) และ**ยืนยันว่า POS ไม่ช้าลง**
6. เพิ่ม unit test ของ `custdisplay/logic.js` ใน `test/` (ใช้ข้อความจริงในข้อ 3–6 เป็น fixture) ให้ `npm test` ผ่าน แล้วขึ้น version และ build/release ตามปกติ

## 10. เฟส 2 (ต่อยอด)

- **เชื่อมกับ QR ล็อกยอด:** เมื่อหน้า Pay มียอดในช่อง `เงินโอน` อาจเปิด QR ของ qrlock ตามยอดนั้นอัตโนมัติ (แทนการกด F9 แล้วพิมพ์ยอดเอง) ต้องให้ Boss ตัดสินใจก่อน เพราะเป็นส่วนที่เกี่ยวกับเงิน
- หน้าต้อนรับหมุนรูปโปรโมชั่นหรือสินค้าแนะนำ
- เสียงหรือแอนิเมชันริสุซังตอนจ่ายเงินเสร็จ

## 11. เก็บกวาด

com0com (COM10↔COM11) ที่ลงไว้ตอนทดสอบไม่ได้ใช้แล้ว ถอนการติดตั้งได้ หรือเปิด Setup ของ com0com แล้วพิมพ์ `remove 0`, `remove 1`, `remove 2`
ใน POS ต้อง **ไม่ติ๊ก** Customer Display ทั้งสองช่อง ไม่อย่างนั้นจะมี error เด้งทุกบิล
