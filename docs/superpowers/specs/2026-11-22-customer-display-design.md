# จอลูกค้า (Customer Display) — ดีไซน์

วันที่ 22/11/2569 · ร้านอึ้งลักเส็ง · ต่อยอดโมดูล QR-LOCK ใน POS Hero
แผนต้นทางที่ทดสอบแล้ว: `customer-display-plan.md` (Boss เขียน) — เอกสารนี้สรุปทิศทางและสิ่งที่ตัดสินใจเพิ่ม

## 1. เจตนา (ทำไม)

ลูกค้าหน้าเคาน์เตอร์ควรเห็นสินค้าที่ยิง ราคา ยอดรวม และตอนจ่ายเงินเห็น "รับเงิน / เงินทอน" ตัวใหญ่
Sea & Hill POS v1.1.17 มีแท็บ Customer Display แต่ใช้ไม่ได้ (Serial: ช่อง Data Bits ผิด ค่าแก้ไม่ได้, Android: ไม่มีพอร์ตรอ)
จึงอ่านข้อความจากหน้าต่าง POS ด้วย UI Automation แล้วส่งขึ้นจอที่ร้านมีอยู่แล้ว

ที่ร้านใช้มือถือ Android เครื่องเดียวทำสองหน้าที่: เป็นจอลูกค้า และเป็นเครื่องรับเงินโอน/โครงการรัฐ (ต้องสลับไปแอปถุงเงิน)
สลับแอปด้วยปุ่มลัดผ่าน ADB อยู่แล้ว (`Ctrl+F10` ไปแอปรับเงิน, `Ctrl+F11` กลับจอลูกค้า)

## 2. เป้าหมาย / ไม่ใช่เป้าหมาย / สิ่งที่ถือว่าล้มเหลว

**เป้าหมาย**
- จอแสดงรายการสินค้า ยอดรวม และหน้าจ่ายเงิน (ยอดชำระ / รับเงิน / เงินทอน) ภายใน ~1 วินาทีหลังพนักงานยิงสินค้า
- ใช้จอ/URL/มือถือเครื่องเดิมของ QR-LOCK ไม่ต้องตั้งค่าอุปกรณ์เพิ่ม
- เมื่อบันทึกบิลแล้ว มือถือกลับหน้าจอลูกค้าเองได้ (ตัวเลือก ปิดเป็นค่าเริ่มต้น)

**ไม่ใช่เป้าหมาย**
- ไม่สลับไปแอปถุงเงินอัตโนมัติ (POS ไม่บอกวิธีจ่ายตั้งแต่เปิด Pay ทำอย่างปลอดภัยไม่ได้)
- ไม่อ่านตารางรายการ Line 1–8 (custom grid อ่านไม่ได้) สร้างรายการเองจากแถบเหลือง
- ไม่ทำเฟส 2 (QR ตามช่องเงินโอน, รูปโปรโมชันหมุน, เสียงริสุซัง) QR-LOCK เดิมครอบคลุม QR อยู่แล้ว

**ถือว่าล้มเหลวแม้ทำงานได้**
- POS ช้าลง ค้าง หรือมี error เด้ง / posreader ส่งคีย์ คลิก หรือแก้ไฟล์/registry ของ Sea & Hill
- จอลูกค้าแสดงยอดผิดโดยไม่รู้ตัว (ต้อง fallback เมื่อรายการรวมไม่ตรง Total)
- กระทบการรับเงินเดิม (inbox, LAN relay, UDP, Pushbullet, พิมพ์สลิป) หรือทำ `test/smoke.js` ตก

## 3. ข้อจำกัด

- ห้ามแตะ logic ส่วนรับเงิน; โค้ดใหม่ต้องแยกโมดูล พังแล้วไม่กระทบ POS (เหมือนที่ QR-LOCK ทำ)
- repo เป็น public: ห้าม commit URL Sheet/Apps Script, key, token และห้าม commit ไฟล์ `.exe`
- ห้ามเปลี่ยน `MINI_WIDTH` / `MINI_HEIGHT` โดยไม่แก้ CSS คู่กัน (ไม่น่าเกี่ยวกับงานนี้)
- ข้อความ UI และสรุปงานเป็นภาษาไทยทั้งหมด
- ทำบน branch แยก (`feat/customer-display`) เปิด PR ห้าม push ลง main
- ห้ามหาช่องใน POS ด้วย AutomationId (เป็น HWND เปลี่ยนทุกครั้งที่เปิด) ใช้รูปแบบข้อความ + ClassName

## 4. ทางที่พิจารณา

**4.1 การสลับมือถือ** (Boss ให้ตัดสินใจเอง → เลือก B)
- A: สลับเองด้วยปุ่มลัดเหมือนเดิม — เสี่ยงน้อยสุด แต่ลืมกลับจอลูกค้าแล้วลูกค้าถัดไปเห็นหน้าแอปถุงเงินค้าง
- **B (เลือก): A + กลับหน้าจอลูกค้าอัตโนมัติเมื่อ "บันทึกบิลแล้ว"** ใช้ `phone.openDisplay` เดิม เป็นตัวเลือกใหม่ในหน้าควบคุมมือถือ ค่าเริ่มต้นปิด
- C: สลับไปถุงเงินเองด้วย — ตัดทิ้ง รู้วิธีจ่ายไม่ได้ตอน Pay เปิด

**4.2 การรัน posreader** (ผมตัดสินใจ)
- **เลือก:** ไฟล์ `.cs` อยู่ใน repo, POS Hero คอมไพล์ด้วย `csc.exe` ของ Windows ลง `userData` ครั้งแรก/เมื่อเวอร์ชันซอร์สเปลี่ยน แล้ว spawn เป็นโปรเซสลูก อ่าน JSON lines จาก stdout
- ไม่เลือก: commit `.exe` (repo public, ตรวจสอบไม่ได้) / PowerShell Add-Type ค้างตลอด (หนักกว่า ควบคุม cache element ยากกว่า)

**4.3 จอ**
- **เลือก:** ใช้ `qrlock/display.html` + `display-server.js` เดิม เพิ่มข้อความชนิดใหม่ (`cart`, `pay`, `thanks`) ผ่าน WebSocket เดิม; ข้อความ QR (`show_qr`, `paid`, `expired`, `cancelled`) แสดงทับหน้าใหม่เสมอ
- ไม่เลือก: หน้าแยก/พอร์ตแยก (ต้องตั้งมือถือใหม่, QR กับตะกร้าสลับกันไม่ได้)

## 5. การออกแบบ

### 5.1 ส่วนประกอบ
```
Sea & Hill POS --UIA อ่านอย่างเดียว--> posreader.exe --JSON lines--> posreader-bridge (Node, ใน qrlock/ หรือโมดูลข้างเคียง)
   --> state machine (cart-state.js, pure, เทสต์ได้) --> display-server.broadcast --> Chrome บนมือถือ/แท็บเล็ต
```
- `customerdisplay/posreader.cs` — C# .NET Framework 4.x อ้าง `UIAutomationClient.dll`/`UIAutomationTypes.dll`
- `customerdisplay/reader-host.js` — คอมไพล์ + spawn + restart เมื่อ exit + แปลง JSON lines เป็นอีเวนต์
- `customerdisplay/cart-state.js` — state machine ล้วน (ไม่พึ่ง electron/IO) รับอีเวนต์ คืนข้อความจอ
- `customerdisplay/parse-line.js` — parse แถบเหลือง
- แก้ `qrlock/display.html` เพิ่มมุมมองรายการ/จ่ายเงิน/ขอบคุณ + รหัสเครื่องที่มุมจอ
- แก้ `qrlock/qrlock-main.js` ต่อ reader-host เข้ากับ `send()` และตัวเลือกกลับจอลูกค้าอัตโนมัติ; เปิด/ปิดพร้อมสวิตช์ "QR ล็อกยอด" (`enabled`) ไม่มีสวิตช์ใหม่

### 5.2 posreader (อ่านอย่างเดียว)
- หาหน้าต่างหลัก: top-level `Name` มี `Sea And Hill POS`; ช่องที่ใช้คือ `ClassName` ขึ้นต้น `WindowsForms10.STATIC`, ค่าใน `Current.Name`
- หาช่องจากรูปแบบข้อความ: Total `^-?[\d,]+\.\d{2}$`, ใบเสร็จ `^POS\d+-\d+$`, รหัสเครื่อง `^POS\d+$`, แถบเหลืองตามข้อ 5.3
- cache element ของช่องหลักหลังหาเจอ; เจอ `ElementNotAvailableException` หรือ POS ปิดเปิดใหม่ค่อยค้นใหม่; ห้าม FindAll ทั้งหน้าต่างทุกรอบ
- poll ทุก 300 ms ส่ง stdout 1 บรรทัด JSON **เฉพาะตอนค่าเปลี่ยน**:
  `{"t":"main","machine":"POS02","receipt":"...","total":225.00,"line":"..."}`, `{"t":"pay","due":..,"cash":..,"change":..,"transfer":null}`, `{"t":"pay_closed"}`, `{"t":"pos_missing"}`
- หน้าต่าง Pay: `Name = "Pay"` ใน process เดียวกับ POS (ตรวจ ProcessId ทุกรอบ); จับคู่ป้ายกับช่อง `WindowsForms10.EDIT` ด้วย `BoundingRectangle` (ศูนย์กลางแนวตั้งอยู่ในช่วงสูงของป้าย, `EDIT.Left >= ป้าย.Right`, เลือกใกล้สุด) ป้าย: `รวมทั้งสิ้น :`, `คงเหลือทั้งสิ้น :` (ถ้ามีใช้เป็นยอดชำระ), `ชำระเงินสด :`, `เงินทอน :`, `เงินโอน :`
- POS ยังไม่เปิด → ส่ง `pos_missing` แล้วลองใหม่ทุก 2 วินาที ห้าม crash
- โหมดดีบัก `--record file.jsonl` เขียนอีเวนต์ลงไฟล์ และ reader-host รองรับ `--replay file.jsonl` สำหรับพัฒนาหน้าเว็บโดยไม่ต้องยิงสินค้าจริง

### 5.3 แถบเหลือง
รูปแบบ `[เพิ่ม : | ลบ : ]<barcode>/<ชื่อ>/<หน่วย>/@ <จำนวน> x <ราคา> = <ยอด>`
- ไม่มี prefix หรือ `เพิ่ม :` → upsert ตาม barcode โดย "จำนวน" คือจำนวนรวมของบรรทัด; `ลบ :` → ลบ barcode นั้น
- parse จากขวาไปซ้าย (ชื่ออาจมี `/`): ตัด prefix (ยอมช่องว่างรอบ `:`) → barcode = ก่อน `/` แรก → แยกท้ายด้วย `/@ ` ตัวสุดท้าย → หน่วย = หลัง `/` สุดท้ายก่อน `/@`, ชื่อ = ส่วนกลาง; ตัด comma ก่อนแปลงตัวเลข

### 5.4 State machine (cart-state.js)
- เลขที่ใบเสร็จเปลี่ยน → บิลใหม่: ล้างรายการ, จำข้อความแถบเหลืองปัจจุบันเป็น baseline (ห้ามนับจนกว่าจะเปลี่ยนจาก baseline)
- แถบเหลืองเปลี่ยน → parse แล้ว upsert/ลบ, ไฮไลต์รายการล่าสุด
- **Total ใช้ค่าจาก POS เสมอ ห้ามคำนวณเอง**
- ถ้า `sum(ยอดรายการ)` ต่างจาก Total เกิน 0.01 (Recall Bill, ส่วนลด, แก้ราคา) → ซ่อนรายการ แสดงเฉพาะรายการล่าสุด + Total และเขียน log ดีบัก
- Total = 0 และไม่มีรายการ → หน้าต้อนรับเดิม
- Pay เปิด → ข้อความ `pay` (ยอดชำระ/รับเงิน/เงินทอน ตัวใหญ่)
- Pay ปิด + เลขที่ใบเสร็จเปลี่ยน → `thanks` พร้อมเงินทอนล่าสุดค้าง ~8 วินาที แล้วกลับหน้าต้อนรับ; **ณ จุดนี้ ถ้าเปิดตัวเลือก ให้สั่งมือถือกลับหน้าจอลูกค้า**
- Pay ปิด + เลขที่ใบเสร็จเดิม → Cancel: กลับหน้ารายการ
- ลำดับความสำคัญของจอ: QR-LOCK (`show_qr`/`paid`/`expired`/`cancelled`) > pay > thanks > cart > welcome

### 5.5 เครือข่ายและตั้งค่า
- พอร์ตเริ่มต้น `displayPort` เปลี่ยน 8080 → **8790** (ในเครื่อง POS02 มีโปรแกรมอื่นใช้ 8080 และ 8788)
- ผู้ใช้ที่ config เดิมเป็น 8080 ย้ายเป็น 8790 อัตโนมัติ (ครั้งเดียว) และกดปุ่ม firewall rule เดิมใหม่ให้ใช้พอร์ตใหม่; หน้า "เชื่อมจอลูกค้า" แสดง URL/QR ใหม่ — **ต้องบอกใน PR/สรุปว่ามือถือต้องเปิด URL ใหม่ครั้งเดียว**
- ตัวเลือกใหม่ `phone.autoDisplayAfterBill` (ค่าเริ่มต้น false) ในหน้า "ควบคุมมือถือ" ข้างตัวเลือก `autoDisplayOnQr` เดิม
- 2 เครื่อง POS: แต่ละเครื่องรัน posreader + server ของตัวเอง แสดงรหัสเครื่อง (`POS02`) เล็กๆ ที่มุมจอ

## 6. การทดสอบ / เกณฑ์ผ่าน

- เทสต์หน่วยแบบ node ธรรมดา (เข้า `test/run-all.js`): `parse-line` (ทุกเคสในข้อ 5.3 รวมชื่อมี `/`, comma, ลบ, ช่องว่างรอบ `:`), `cart-state` (บิลใหม่+baseline, upsert, ลบ, mismatch fallback, Pay เปิด/ปิด/Cancel, ลำดับความสำคัญกับ QR), `reader-host` (restart, parse JSON lines เสีย), พอร์ตย้าย 8080→8790
- ทดสอบกับ POS จริง (Boss/ผู้ใช้ทำ, ผมให้เช็กลิสต์): ยิงใหม่, ยิงซ้ำ, +1/-1, ลบ, เปิด Pay, Cancel, Save, บิลถัดไป, Hold/Recall, `5*barcode`, ส่วนลด, สมาชิก, ปิดเปิด POS ระหว่างรัน, POS ค้าง
- วัดว่า CPU ของ posreader ไม่เกิน ~1–2% และ POS ไม่ช้าลง
- `test/smoke.js` และเทสต์เดิมทั้งหมดต้องผ่าน

## 7. ปล่อยให้ผู้สร้างตัดสินใจ

- ชื่อโฟลเดอร์/ไฟล์ย่อยและหน้าตาเลย์เอาต์ละเอียดของมุมมองรายการ (ตามแนวเดิม: แนวนอน รายการซ้าย ยอดรวมขวาล่าง ฟอนต์ใหญ่ อ่านได้ระยะ 1–1.5 ม. ธีมแดง-ทอง)
- วิธีคอมไพล์ csc ที่ละเอียด (ตำแหน่ง csc.exe, cache ตามแฮชซอร์ส) และข้อความ error ที่แสดงเมื่อไม่มี csc
- รูปแบบ log ดีบัก
- วิธีเริ่มต้นอัตโนมัติ: ผูกกับ POS Hero ที่เปิดพร้อมเครื่องอยู่แล้ว (ไม่ต้องทำ Startup แยก)

## 9. ข้อสรุปเพิ่มหลังผู้ตรวจอ่าน (ตัวหนา = ผมตัดสินเอง Boss ตรวจได้)

**ตอบจากแผนของ Boss แล้ว (ไม่ต้องเดา)**
- Total: ในหน้าหลักมี STATIC ที่เป็นตัวเลขล้วนรูปแบบ `^-?[\d,]+\.\d{2}$` **ช่องเดียว** (ยืนยันแล้วในแผน) ถ้าเจอมากกว่า 1 ช่อง ให้ถือว่าอ่านไม่ได้: ไม่อัปเดต Total เขียน log และใช้หน้ารายการล่าสุดเท่านั้น
- เลขที่ใบเสร็จเปลี่ยนตอนเริ่มบิลใหม่; แถบเหลืองยังค้างข้อความจากบิลก่อน (จึงมีกฎ baseline) — ทั้งสองข้อทดสอบแล้ว
- ข้อความจริงที่ทดสอบแล้ว ใช้เป็นเคสเทสต์: `8850822011676/เค.เอ. ไฮยาอินเทนส์เซรั่ม 7กรัม/แพ็ค/@ 1.00 x 225.00 = 225.00`, `เพิ่ม : ...@ 2.00 x 225.00 = 450.00`, ใบเสร็จ `POS02261122-00065`, เครื่อง `POS02`, Pay: รวมทั้งสิ้น `225.00`, ชำระเงินสด `500` (ไม่มีทศนิยม), เงินทอน `275.00`

**ผมตัดสินใจ**
- **ไม่มีข้อมูลจริงจาก POS ในเครื่องที่เขียนโค้ด:** ขั้นแรกของแผนงานคือ posreader พร้อม `--record` ให้ Boss บันทึกเซสชันจริงจาก POS ก่อนทำหน้าเว็บ; เทสต์หน่วยใช้ตัวอย่างข้างบน
- **เปิดทำงานพร้อมสวิตช์ "QR ล็อกยอด" เดิม ไม่มีสวิตช์แยก** (ที่ร้านใช้ QR/มือถืออยู่แล้ว) ถ้าอยากเปิดเฉพาะจอรายการภายหลังค่อยเพิ่ม
- **แก้ `package.json`:** เพิ่ม `customerdisplay/**/*` ใน `build.files` และ `asarUnpack` เฉพาะ `posreader.cs` เพื่อให้ csc อ่านได้ในแอปที่แพ็กแล้ว
- **จอที่ต่อใหม่กลางบิล (เช่น สลับแอปแล้วกลับมา):** server ส่งสถานะรวมปัจจุบันตามลำดับความสำคัญ ไม่ใช่ข้อความล่าสุดอย่างเดียว (แก้ `getLastMessage`)
- **ย้ายพอร์ต 8080→8790 ครั้งเดียว** ตามธง `portMigrated` ใน config: ถ้าตอนนั้นเป็น 8080 ให้ย้าย; หลังย้ายแล้ว ผู้ใช้ตั้งกลับเป็น 8080 เองได้และจะไม่ถูกย้ายอีก
